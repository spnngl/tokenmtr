# apps/desktop/src-tauri (Tauri shell)

The shell only maps: one command per `DataSource` method of the UI, each a thin wrapper over a plain function in `src/backend/` (testable without a window), which calls into the crates. Product rules belong in `crates/`.

- The webview holds no plugin permission: native work (dialogs, Finder, notifications) goes through commands, and each window's capability file in `capabilities/` allows only the commands that window calls.
- Response types are mirrored by the UI's Zod schemas; `src/goldens.rs` serializes real values into the UI's fixtures (`just goldens`) so either side drifting fails a test.
- The tray icon is drawn here (`src/tray.rs`, `src/tray/rings.rs`), outside the webview: `Ring::used` repeats the UI's quota thresholds (`meterLevel` in `apps/desktop/src/shared/usage-meter.tsx`) with no test linking them, so change both together.

## Adding a command

1. Name it in `src/command_names.in` (the `snake_case` of the UI method), add the handler to `command_table!` in `src/commands.rs`, and put the work in `src/backend/`.
2. Allow it as `allow-<kebab-name>` in `capabilities/main.json`, and in `capabilities/recap.json` too when the menu-bar recap calls it. No test covers this: a missing entry fails only at runtime, as a permission error.
3. Run `just bindings` to regenerate `apps/desktop/src/shared/bindings.ts`; commit it with `permissions/autogenerated/<name>.toml` and `gen/schemas/`, which the build script writes.
4. UI side: the method in `apps/desktop/src/shared/data-source.ts`, its Zod-parsed call in `apps/desktop/src/shared/tauri-data-source.ts`, the mock in `apps/desktop/src/shared/mock/`.
5. A read command: add its golden value in `src/goldens.rs`, a case in `apps/desktop/src/shared/schemas/golden.test.ts`, then run `just goldens`.

Done when `just check` passes (it covers this crate and the UI's binding and golden tests).
